# 企业微信批量转发 RPA 用户使用手册

## 简要概述

本工具用于在 Windows 企业微信桌面端，将用户已经手动勾选的消息分批转发给会话列表底部的若干会话。推荐先用 **Dry-run 自检**确认参数和运行环境，再进行真实发送。真实发送前，务必人工核对源消息、发送数量、每批数量、会话列表顺序和哨兵名称；程序不会区分群聊、员工私聊或机器人，符合位置条件的会话都有可能被选中。每批最多选择 9 个会话，默认急停快捷键为 `Ctrl+Alt+Q`。

最常用的 GUI 操作顺序如下：

1. 登录企业微信，进入源会话，手动进入消息多选并勾选待转发消息。
2. 启动本工具，填写发送数量、每批数量、批次间隔及哨兵设置。
3. 选择 **Dry-run 自检**，点击 **检查环境**，确认源消息识别结果正确。
4. 完成 Dry-run 后，如确需发送，切换为 **真实发送**，勾选两个确认项。
5. 再次点击 **检查环境**；检查成功后点击 **启动运行**，输入大写 `SEND`。
6. 运行期间不要操作企业微信；如发现异常，点击 **立即停止**或按 `Ctrl+Alt+Q`。
7. 运行完成后核对结果弹窗、日志和截图。

> **重要提示：** 本工具是基于窗口坐标、截图、图像识别和 OCR 的桌面自动化程序，不是企业微信官方接口。界面版本、窗口遮挡、显示缩放、网络延迟、会话排序变化或识别误差都可能影响结果。真实发送前必须由操作者完成最终人工确认。

## 1. 工具用途与适用范围

### 1.1 主要用途

本工具适用于以下场景：

- 将同一组已选消息转发给多个企业微信会话；
- 按指定总数量分批处理收件会话；
- 从“选择聊天/发送给”弹窗的会话列表底部开始，向上连续选择收件会话；
- 使用一个或多个“哨兵”会话名称限制发送边界；
- 通过 Dry-run、运行日志、参数快照和过程截图辅助检查与追溯。

### 1.2 当前不支持的能力

当前版本不提供以下能力：

- 不读取 CSV 群列表，也不能按外部名单精确搜索或指定收件人；
- 不区分群聊、员工私聊或机器人；
- 不使用 YAML 配置文件；
- 不使用 SQLite 状态库，不记录已完成收件人；
- 不支持断点续跑；
- 不保证与企业微信所有版本、所有界面布局或所有显示设置兼容；
- 收件人选择模式仅支持从会话列表底部向上选择。

中断或失败后重新运行时，程序会再次从会话列表底部开始。重新运行前必须重新检查列表顺序，并评估重复发送风险。

## 2. 使用前准备

### 2.1 环境要求

- Windows 操作系统；
- 已安装并可正常使用的企业微信桌面端；
- 企业微信账号已登录，并具有向目标会话发送消息的权限；
- 使用完整解压后的程序目录，不要只复制单个 `.exe` 或 `.bat` 文件；
- OCR 模型及程序依赖完整。发布包中应保留随包提供的模型和程序文件。

### 2.2 企业微信准备

运行前请完成以下操作：

1. 打开并登录企业微信。
2. 进入包含待转发消息的源会话。
3. 手动进入消息多选状态。
4. 勾选本次需要转发的全部源消息。
5. 确认勾选的是正确消息，没有包含敏感、过期或不应外发的内容。
6. 确认企业微信没有被其他窗口遮挡，且运行期间不会自动锁屏、休眠或切换用户。

建议先关闭可能抢占焦点的弹窗、通知或远程控制操作。工具运行期间不要使用鼠标、键盘操作企业微信。

### 2.3 收件会话准备

程序会在收件人弹窗中将会话列表滚动到底部，然后从底部向上连续选择。真实发送前请人工确认：

- 当前会话列表底部的顺序符合预期；
- 计划范围内没有不应接收消息的员工、群聊或机器人；
- “发送数量”不会越过允许的范围；
- 如使用哨兵，哨兵名称准确、唯一且能被当前界面完整显示；
- 会话名称没有容易被 OCR 混淆的特殊字符、同名项或过长截断情况。

## 3. 参数说明

### 3.1 运行模式

#### Dry-run 自检

Dry-run 是默认模式，不点击最终发送按钮，不会真实发送消息。它用于检查参数、源消息勾选状态、OCR 环境及基本运行逻辑。

Dry-run 不能证明真实发送一定成功，也不能完全覆盖真实发送过程中的窗口点击、滚动、会话选择和网络状态。完成 Dry-run 后，仍需人工复核真实发送条件。

#### 真实发送

真实发送会实际操作企业微信并发送消息。GUI 中必须同时满足以下条件：

- 选择 **真实发送**；
- 勾选“我理解这会真实发送企业微信消息”；
- 勾选“我已人工确认源消息和哨兵配置正确”；
- 重新完成 **检查环境**；
- 启动时准确输入大写 `SEND`。

### 3.2 发送数量

“发送数量”是本次计划处理的收件会话总数，必须大于 0。

实际发送数量可能小于计划数量，例如：

- 命中哨兵边界；
- 用户主动停止；
- OCR 或图像复核失败；
- 企业微信窗口、弹窗或控件未找到；
- 可选择的会话数量不足；
- 运行中出现其他安全停止条件。

### 3.3 每批数量

“每批数量”是每个批次最多选择的收件会话数：

- 必须大于 0；
- 最大为 9；
- 最后一批会按剩余数量处理。

例如，发送数量为 20、每批数量为 9 时，计划分为 9、9、2 三批。

### 3.4 间隔秒

“间隔秒”是相邻批次之间的等待时间，不能为负数。网络较慢、电脑性能较低或企业微信响应较慢时，可适当增大该值。

### 3.5 哨兵边界

哨兵用于限制发送边界。启用后，程序会通过 OCR 识别本批已选会话名称：

- 如果命中哨兵，哨兵本身及其上方的已选会话会被取消选择；
- 只向哨兵下方的会话发送；
- 完成该尾批后结束整个任务；
- 如果哨兵识别、截断或截断后的数量复核失败，程序会停止，以降低越界发送风险。

多个哨兵名称在 GUI 中使用逗号分隔。名称应与企业微信界面显示一致。不要把哨兵当作绝对安全保证：OCR 可能受字体、缩放、遮挡、名称截断或界面变化影响。

## 4. GUI 操作说明（推荐）

### 4.1 启动程序

发布包用户双击：

```text
run-gui.bat
```

开发环境可使用：

```powershell
.\.venv-paddle-win\Scripts\python.exe -m wecom_rpa.gui
```

如果提示找不到 `app\wecom-rpa-gui.exe`，请确认发布包已经完整解压，并从完整程序目录运行脚本。

### 4.2 建议先执行 Dry-run

1. 在企业微信中完成源消息勾选。
2. 在工具中选择 **Dry-run 自检**。
3. 填写发送数量、每批数量和间隔秒。
4. 按需启用哨兵并填写名称。
5. 点击 **检查环境**。
6. 查看检查结果，确认识别到的源消息数量与人工勾选数量一致，并确认已识别“逐条转发”按钮。
7. 点击 **启动运行**，在确认弹窗中继续。
8. 查看运行日志与完成结果。Dry-run 的实际发送数量应为 0。

### 4.3 执行真实发送

1. 再次人工核对源消息内容和数量。
2. 核对收件人列表底部顺序、发送数量和哨兵边界。
3. 将运行模式切换为 **真实发送**。
4. 勾选两个真实发送确认项。
5. 点击 **检查环境**。
6. 确认检查结果中的源消息数量正确。
7. 点击 **启动运行**。
8. 在确认框中输入大写 `SEND`。
9. 运行期间不要移动企业微信窗口、切换会话、滚动列表或操作鼠标键盘。
10. 完成后核对弹窗中的计划数量、实际发送数量和总耗时，并抽查企业微信发送结果。

### 4.4 “检查环境”会做什么

“检查环境”主要执行以下操作：

1. 校验参数和真实发送确认项；
2. 定位、激活并最大化企业微信窗口；
3. 保存检查截图；
4. 识别当前源消息的蓝色已选框；
5. 使用 OCR 识别底部工具栏的“逐条转发”按钮；
6. 记录源消息行坐标和按钮坐标，供本次运行使用；
7. 显示检查结果。

修改任何运行参数后，原检查结果会失效，必须重新点击 **检查环境**。如果企业微信界面、窗口位置、源消息勾选状态或显示设置发生变化，也应重新检查。

### 4.5 程序运行过程

真实发送时，程序通常按以下顺序处理：

1. 定位并激活企业微信窗口；
2. 复核或重新勾选已记录的源消息；
3. 点击“逐条转发”，打开收件人选择弹窗；
4. 将左侧会话列表滚动到底部，并通过截图差异确认滚动生效及列表已稳定；
5. 从底部向上勾选本批会话；
6. 复核已选数量；
7. 如启用哨兵，识别名称并按边界截断；
8. 点击最终发送按钮；
9. 检查收件人弹窗是否已关闭；
10. 等待设置的批次间隔后继续下一批。

程序停止并不代表已经撤回本批此前完成的发送。急停后请先检查企业微信实际状态，再决定是否重新运行。

## 5. 停止、失败与重新运行

### 5.1 主动停止

可使用以下任一方式请求停止：

- 点击 GUI 中的 **立即停止**；
- 按默认急停快捷键 `Ctrl+Alt+Q`。

“立即停止”只结束当前任务，不关闭 GUI。停止请求通常会在当前可中断步骤生效，不保证能撤销已经发生的点击或发送。

### 5.2 自动停止条件

出现以下情况时，程序可能停止或报错：

- 找不到企业微信窗口；
- 找不到源消息蓝色勾选框或“逐条转发”按钮；
- 收件人弹窗未打开或意外关闭；
- 滚动条拖动无效，或无法确认列表已到底部；
- 找不到足够的收件人复选框；
- 已勾选数量与计划数量不一致；
- 哨兵 OCR、截断或截断后复核失败；
- 点击发送后收件人弹窗仍存在；
- 企业微信无响应、界面变化或运行环境异常。

### 5.3 失败后的处理顺序

1. 不要立即重复启动。
2. 查看企业微信当前界面，确认是否已有部分消息发出。
3. 查看完成/错误弹窗中的计划数量和实际发送数量。
4. 查看 `logs\wecom_rpa.log` 的最后一段记录。
5. 查看 `screenshots\errors\` 和相关过程截图。
6. 重新核对会话列表底部顺序和源消息勾选状态。
7. 如需重试，先重新执行 **检查环境**，并重新评估发送数量。

本工具不支持断点续跑。重新运行会再次从列表底部开始，可能造成重复发送。

## 6. CLI 使用说明（高级用户）

普通用户建议使用 GUI。CLI 适合开发、测试或明确了解参数含义的用户。

### 6.1 Dry-run 示例

```powershell
.\.venv-paddle-win\Scripts\python.exe -m wecom_rpa.main `
  --send-count 10 `
  --batch-size 9 `
  --batch-interval-sec 0 `
  --yes `
  --dry-run
```

### 6.2 真实发送示例

```powershell
.\.venv-paddle-win\Scripts\python.exe -m wecom_rpa.main `
  --send-count 50 `
  --batch-size 9 `
  --batch-interval-sec 0 `
  --sentinel-name 大小尘 `
  --yes `
  --no-dry-run `
  --real-send `
  --i-understand-this-will-send-messages
```

CLI 真实发送必须同时提供：

```text
--no-dry-run --real-send --i-understand-this-will-send-messages
```

多个哨兵可以重复使用 `--sentinel-name`。`--yes` 会跳过流程中的人工确认，不能替代真实发送的显式授权；除非用于受控测试且已经完成外部人工复核，否则不建议在真实发送中使用。

## 7. 运行记录与数据安全

程序会在本地保存以下文件：

- `logs\wecom_rpa.log`：操作步骤、坐标、识别结果、异常和步骤耗时；
- `logs\run_snapshots\*.json`：每次启动前的最终参数快照；
- `screenshots\checkpoints\`：检查、滚动、选择和发送后的过程截图；
- `screenshots\errors\`：异常发生时的截图。

这些文件可能包含企业微信界面、会话名称、联系人信息、消息内容或其他业务数据。请做到：

- 仅在受控设备和受控账号下运行；
- 限制日志与截图目录的访问权限；
- 不要未经授权上传、转发或共享日志和截图；
- 按所在组织的数据保留制度定期清理；
- 在提交故障材料前先脱敏。

## 8. 注意事项

### 8.1 必须人工确认的事项

真实发送前，操作者必须确认：

- 源消息内容、条数和勾选状态正确；
- 消息允许发送给计划范围内的所有会话；
- 发送数量和每批数量正确；
- 会话列表底部顺序正确；
- 计划范围内没有无关员工、群聊或机器人；
- 哨兵名称与边界正确；
- 当前账号具备发送权限，并符合组织制度及法律法规；
- 已完成必要的审批、告知或授权。

### 8.2 运行期间禁止或避免的操作

- 不要移动、缩放、最小化或关闭企业微信窗口；
- 不要切换企业微信会话或改变消息多选状态；
- 不要手动滚动收件人列表；
- 不要同时使用鼠标和键盘操作企业微信；
- 不要让其他自动化程序同时控制桌面；
- 避免锁屏、休眠、远程桌面尺寸变化或显示器插拔；
- 避免在网络不稳定、企业微信正在升级或界面异常时运行。

### 8.3 重要风险

- 会话列表可能因新消息、置顶状态或企业微信内部排序规则发生变化；
- 底部连续选择会把员工、机器人和群聊一并视为候选项；
- OCR 可能误识别或无法识别名称；
- 屏幕缩放、分辨率、主题、字体、遮挡和客户端升级可能导致坐标或图像识别失效；
- 急停不能撤回已经发送的消息；
- 重新运行可能重复发送；
- 日志和截图可能包含敏感信息。

## 9. 常见问题与排查

### 9.1 检查环境失败，找不到企业微信窗口

- 确认企业微信桌面端已启动并登录；
- 确认窗口标题包含“企业微信”；
- 关闭登录弹窗、升级弹窗等遮挡界面；
- 重新打开企业微信和本工具后再试。

### 9.2 未识别到源消息蓝色勾选框

- 确认已经进入消息多选状态；
- 确认至少勾选了一条消息；
- 确认勾选框清晰可见，没有被其他窗口遮挡；
- 尝试恢复常用显示缩放和分辨率后重新检查。

### 9.3 未识别到“逐条转发”按钮

- 确认当前处于消息多选状态；
- 确认底部工具栏完整可见；
- 检查 OCR 模型是否完整；
- 关闭遮挡窗口并重新执行检查。

### 9.4 收件人列表无法确认滚动到底部

- 不要手动干预滚动过程；
- 确认收件人弹窗完整显示；
- 检查企业微信是否卡顿；
- 适当增加批次间隔后重新检查和运行；
- 如果重复失败，应停止真实发送并由维护人员检查界面适配。

### 9.5 实际发送数量少于计划数量

可能原因包括命中哨兵、人工停止、安全复核失败、会话数量不足或流程异常。请结合结果弹窗、日志和截图判断，不要仅依据计划数量推断发送结果。

### 9.6 停止后能否继续上次进度

不能。当前版本不保存收件人进度。重新运行会从会话列表底部重新开始，必须先人工核对已发送情况并重新计算发送范围。
