# 企业微信批量转发工具：傻瓜式使用说明

> 适用对象：第一次使用本工具、不了解命令行的普通用户。
>
> 推荐入口：双击 `run-gui.bat`，不要使用其他 `.bat` 文件。

## 先记住这 4 句话

1. 本工具会从企业微信“选择聊天”列表的**最底部开始，向上连续选择会话**。
2. 它**不区分群聊、员工私聊和机器人**，排在范围内的都会被选中。
3. 任何失败或停止后，**先检查是否已经发出一部分，绝对不要马上重新运行**。
4. 紧急停止：点击工具里的“立即停止”，或按键盘 `Ctrl + Alt + Q`。已经发出的消息不会被撤回。

---

## 一、这个工具是做什么的

它可以把你在 Windows 企业微信中已经勾选的消息，分批转发给多个会话。

它不会读取 Excel、CSV 或通讯录名单，也不会按名称逐个搜索收件人。它只会在“选择聊天/发送给”窗口中滚动到列表底部，然后从下往上连续选择。

例如：

- 发送数量填 `20`；
- 每批数量填 `9`；
- 程序会计划分成 `9 + 9 + 2` 三批；
- 每批最多只能选 9 个会话。

## 二、使用前必须准备好

### 1. 检查电脑和程序

- 必须使用 Windows 电脑；
- 企业微信桌面版已经安装、登录并能正常发送消息；
- 程序压缩包已经**完整解压**；
- 不要只把 `run-gui.bat` 或 `.exe` 单独复制到桌面；
- 关闭企业微信的升级提示、登录提示等弹窗；
- 暂时关闭其他会抢鼠标、键盘或窗口焦点的自动化程序；
- 运行期间不要锁屏、休眠、切换显示器或改变远程桌面分辨率。

### 2. 在企业微信中选好要转发的消息

1. 打开企业微信，进入消息所在的会话。
2. 对一条消息点右键，选择“多选”。
3. 勾选本次要转发的全部消息。
4. 逐条核对内容，确认没有多选、漏选、敏感信息或过期内容。
5. 保持这个页面不动，不要退出多选状态。

### 3. 检查收件会话顺序

这是最重要的一步。程序会从收件人列表最底部向上选择，请提前人工确认：

- 列表底部的会话顺序符合预期；
- 发送数量覆盖的范围内没有不该收到消息的人、群或机器人；
- 最近的新消息、置顶变化等没有改变会话排序；
- 如使用“哨兵”，名称与企业微信显示完全一致，且没有同名或被截断的情况。

如果你无法确定列表底部有哪些会话，请不要进行真实发送。

## 三、第一次使用：先做 Dry-run 自检

Dry-run 不会点击最终“发送”按钮，也不会真实发送消息。它主要检查参数、企业微信窗口、源消息蓝色勾选框、OCR 模型和“逐条转发”按钮。

> Dry-run 只是自检，不会完整操作收件人弹窗，不能保证真实发送一定成功。

操作步骤：

1. 双击 `run-gui.bat`。
2. “运行模式”选择 **Dry-run 自检**。
3. 填写以下参数：
   - **发送数量**：本次最多处理多少个会话，必须大于 0；
   - **每批数量**：建议保持 `9`，只能填写 1～9；
   - **间隔秒**：两批之间等待几秒。网络或电脑较慢时建议填 `3`～`5`；
   - **哨兵边界**：不确定含义时不要随意开启，详见下一节。
4. 点击 **检查环境**。
5. 等待“检查完成”弹窗。
6. 核对弹窗中识别到的源消息条数，必须和你手工勾选的条数完全相同。
7. 查看右侧摘要，确认模式、发送数量、每批数量、哨兵名称都正确。
8. 点击 **启动运行**，再确认启动 Dry-run。
9. 完成弹窗中的“实际发送”应为 `0`。

只要修改了任意参数，或者移动了企业微信窗口、改变了消息勾选状态，都必须重新点击“检查环境”。

## 四、“哨兵边界”是什么意思

哨兵是一个用来阻止程序继续向上发送的会话名称。

程序在已选会话中识别到哨兵后，会取消选择哨兵本身以及哨兵上方的会话，只向哨兵下方的会话发送，然后结束任务。

使用方法：

1. 勾选“启用哨兵”。
2. 输入企业微信界面上显示的完整会话名称。
3. 多个名称使用中文逗号 `，` 或英文逗号 `,` 分隔。
4. 真实发送前再次核对名称、位置和列表顺序。

注意：哨兵依赖 OCR 文字识别。字体、显示缩放、遮挡、名称过长、特殊字符或同名会话都可能影响识别。哨兵只能降低风险，不能代替人工检查。

## 五、确认无误后进行真实发送

真实发送前，建议先用 1～2 个专用测试会话做小范围测试。

操作步骤：

1. 再次核对源消息内容和勾选条数。
2. 再次核对收件人列表底部顺序和发送数量。
3. “运行模式”选择 **真实发送**。
4. 勾选下面两个确认框：
   - “我理解这会真实发送企业微信消息”；
   - “我已人工确认源消息和哨兵配置正确”。
5. 点击 **检查环境**。
6. 确认识别到的源消息条数与人工勾选数量完全一致。
7. 点击 **启动运行**。
8. 在确认框中输入大写英文 `SEND`，再继续。
9. 手离开鼠标和键盘，等待程序完成。
10. 运行结束后，核对弹窗里的“计划处理”和“实际发送”，并在企业微信中抽查结果。

运行期间不要：

- 移动、缩放、最小化或关闭企业微信；
- 切换会话、滚动列表或改变消息勾选状态；
- 使用鼠标键盘操作企业微信；
- 打开会遮挡企业微信的窗口；
- 锁屏、休眠、插拔显示器或改变显示缩放；
- 让其他人通过远程控制同时操作电脑。

## 六、需要停止时怎么办

发现选错消息、选错范围、界面卡住或任何异常时：

1. 点击工具窗口里的 **立即停止**；或
2. 按键盘 `Ctrl + Alt + Q`。

停止请求会在程序到达可安全中断的位置后生效，可能不是瞬间停止。已经点击发送的批次不会自动撤回。

停止后不要直接重跑。先检查企业微信中已经发给了哪些会话，再决定后续处理方式。

## 七、报错后统一这样处理

不管看到什么报错，都先按下面顺序处理：

1. **不要立即重新运行。**
2. 查看企业微信当前停在哪个页面，确认是否已经发送了一部分。
3. 记下错误弹窗的完整文字，最好拍照或截图。
4. 点击 **打开日志目录**，保留 `wecom_rpa.log`。
5. 点击 **打开截图目录**，查看 `errors` 和 `checkpoints` 文件夹中的最新截图。
6. 重新核对源消息、会话列表底部顺序、发送数量和哨兵。
7. 能确定不会重复发送后，再回到正确页面，重新勾选源消息并重新“检查环境”。
8. 仍然失败时，把错误文字、日志和最新错误截图交给维护人员。发送前注意对敏感内容脱敏。

本工具不记录已经完成的收件人，也不支持从中断处继续。重新运行会再次从会话列表底部开始，可能重复发送。

## 八、常见报错对照表

| 看到的现象或提示 | 常见原因 | 应该怎么做 |
| --- | --- | --- |
| 双击 `run-gui.bat` 后提示找不到 `app\wecom-rpa-gui.exe` | 安装包未完整解压，或只复制了启动文件 | 重新完整解压整个发布包，在解压后的原目录运行；不要单独移动 `.bat` 或 `.exe` |
| “发送数量必须 > 0” | 发送数量为空、为 0 或为负数 | 填写大于 0 的整数 |
| “每批数量必须是大于 0 的整数”或“batch_size 不能超过 9” | 每批数量格式错误或超过 9 | 填写 1～9，建议填 9 |
| “间隔秒必须是大于等于 0 的数字” | 填了负数或非数字 | 填 0 或正数；电脑较慢可填 3～5 |
| “真实发送确认未完成” | 没有勾选两个确认框 | 核对内容和边界后，勾选两个确认框，再重新检查环境 |
| “未找到企业微信窗口” | 企业微信没启动、未登录、存在登录/升级弹窗或窗口异常 | 打开并登录企业微信，关闭弹窗，恢复主窗口后重试 |
| “未检测到待转发消息蓝色勾选框” | 没进入消息多选、没有勾选消息、页面被遮挡或显示设置变化 | 回到源会话，重新进入多选并勾选消息，确保勾选框可见后重新检查 |
| “未识别到‘逐条转发’按钮” | 不在多选状态、底部工具栏被遮挡、OCR 模型不完整或界面版本变化 | 确保底部工具栏完整可见；重启后仍失败则运行 `check-ocr-models.bat`，并联系维护人员 |
| 出现“OCR 离线模型检查提示” | OCR 模型缺失、目录不完整或依赖无法加载 | 不要真实发送；确认发布包完整，运行 `check-ocr-models.bat`，把结果交给维护人员 |
| “点击逐条转发后未识别到发送给弹窗” | 企业微信响应慢、窗口被挡住或界面发生变化 | 先确认是否有消息发出；关闭遮挡窗口，可增加间隔秒后重新检查；反复失败则停止使用并联系维护人员 |
| “未识别到足够的会话复选框” | 列表可见数量不足、弹窗尺寸变化或识别失败 | 不要手动补点；保留截图和日志，恢复标准窗口后重新检查 |
| “勾选收件人数量复核失败” | 点击未生效、界面卡顿或识别结果不一致 | 先确认是否部分发送；不要直接重跑；保留日志和错误截图 |
| “滚动条失败”“无法确认已经到底部” | 收件人弹窗卡顿、滚动条位置变化或程序无法确认列表底部 | 不要手动继续发送；关闭本次运行，恢复企业微信后再试；反复失败需维护人员适配 |
| “哨兵识别/截断/复核失败” | 名称识别错误、同名、名称截断、缩放或遮挡影响 OCR | 不要越过报错继续；人工核对边界和实际已发送范围，修正哨兵后重新检查 |
| “源消息勾选数量或位置不符合记录” | 检查后移动了窗口、滚动了消息、改变了勾选或界面发生变化 | 回到源消息，重新勾选并重新检查环境 |
| “发送后仍检测到收件人弹窗”或“无法确认本批发送结果” | 发送可能未成功、也可能界面没有及时关闭 | 按“结果未知”处理：立刻人工检查企业微信实际发送情况，未查清前禁止重跑 |
| 点击“立即停止”后没有马上停 | 程序正在执行一个不可立即中断的桌面操作 | 不要继续操作企业微信，等待状态返回；必要时按 `Ctrl + Alt + Q` |

## 九、如何把问题交给维护人员

请一次性提供以下信息，排查会快很多：

- 报错发生的大概时间；
- 错误弹窗的完整文字；
- 当时选择的是 Dry-run 还是真实发送；
- 发送数量、每批数量、间隔秒和哨兵名称；
- 源消息人工勾选条数；
- 是否已经发现部分消息发出；
- `logs\wecom_rpa.log`；
- `screenshots\errors\` 中最新截图；
- `screenshots\checkpoints\` 中报错前后的最新截图。

日志和截图可能包含消息内容、联系人、群名或其他业务数据。对外发送前必须脱敏，不要上传到公开网盘、公开群聊或无权限的位置。

## 十、每次发送前后的检查清单

### 发送前

- [ ] 企业微信已登录，没有升级、登录等弹窗；
- [ ] 源会话正确，源消息内容和条数正确；
- [ ] 收件人列表底部顺序已经人工确认；
- [ ] 发送数量和每批数量正确；
- [ ] 哨兵名称和位置正确，或明确决定不使用哨兵；
- [ ] 已完成 Dry-run；
- [ ] 已重新点击“检查环境”，识别条数完全一致；
- [ ] 已完成必要的业务审批、保密和隐私确认；
- [ ] 知道急停方式是 `Ctrl + Alt + Q`。

### 发送中

- [ ] 不碰鼠标和键盘；
- [ ] 不移动、遮挡或缩放企业微信；
- [ ] 发现异常立即停止。

### 发送后

- [ ] 核对计划数量和实际发送数量；
- [ ] 在企业微信中抽查实际结果；
- [ ] 停止或失败时，已确认是否部分发送；
- [ ] 日志和截图已按公司规定保管或清理。

## 十一、最后提醒

本工具是通过截图、OCR 和鼠标点击操作企业微信的桌面自动化工具，不是企业微信官方接口。企业微信升级、界面变化、分辨率和缩放、窗口遮挡、网络延迟、会话排序变化都可能导致识别或点击失败。

如果你无法确认源消息、收件人范围、列表顺序或报错后的实际发送结果，请停止使用真实发送并联系维护人员。
